### Purpose

In-Staff provides an enterprise-grade, server-centric administration, moderation, and security suite for Minecraft 1.21.1:

1. **Moderation Engine** — Unified UUID-based punishment system supporting bans, temp-bans, mutes, temp-mutes, timeouts, player freezing, and audit history.
2. **Dynamic Maintenance** — Instant maintenance mode locking general logins with customizable MOTD and staff-only bypass.
3. **Smart Whitelist** — In-game dynamic whitelist supporting reload-on-the-fly and localized custom kick messages.
4. **Activity & Playtime Tracker** — Accurate session tracking, total accumulated playtime, and last-seen telemetry.
5. **Live & Offline Invsee** — Interactive live synchronization for online inventory, Ender Chest, and Curios accessories, plus offline `playerdata/<UUID>.dat` manipulation.
6. **Ban-Item System** — Item-level restriction engine offering total confiscation, use-only denial, and block-placement denial.
7. **Safe-Unload & Chunk Quarantine** — Ticking block entity / entity crash interception, preventing corrupted objects from crashing the entire world.
8. **Client Integrity Handshake** — Network packet payload verifying client mod and resource pack hashes during login.

## 3. Subsystem Architecture

### 3.1 Moderation Engine (`moderation/`)

- **Identifier**: Always UUID-based. Lookups from names are resolved via `ServerPlayer` or the server's `GameProfileCache`.
- **Punishment Lifecycle**:
  - **Bans**: Intercepted in `ServerConfigurationListener` and `PlayerEvent.PlayerLoggedInEvent`. If active, the player is rejected with the configured ban screen (showing reason, issuer, and expiry).
  - **Mutes**: Intercepted in `ServerChatEvent` and private message commands (`/tell`, `/msg`, `/w`). Blocked messages notify the muted player with remaining time.
  - **Freezes**: Clamps movement in `PlayerTickEvent`, preventing position, rotation, jumping, and interactions until unfrozen.
- **Audit History**: Every sanction (active or expired) remains recorded in `instaff/punishments_history.json` for staff auditing via `/history <player>`.

### 3.2 Access & Maintenance (`access/`)

- **Maintenance Mode**:
  - Toggled via `/maintenance on|off`.
  - When active:
    - Server List Ping (`ClientboundStatusResponsePacket` / `ServerStatus`) reflects the maintenance MOTD.
    - Incoming logins from players without permission `instaff.maintenance.bypass` (OP level 2+) are rejected with `inrp.maintenance.kick_message`.
- **Dynamic Whitelist**:
  - Operates alongside or replaces the vanilla whitelist with instant reload capabilities and customized kick messages.
- **Playtime Tracker**:
  - Captures `loginTime` on `PlayerLoggedInEvent`.
  - Accumulates session elapsed time on `PlayerLoggedOutEvent` into `instaff/playtime.json`.

### 3.3 Inspection & Invsee (`inspection/`)

- **Live Synchronization**:
  - Online targets share their `Inventory` and `EnderChest` directly through customized container menus (`InvseeMenu`).
  - Edits made by staff are immediately reflected in the target player's inventory in real time.
- **Offline Inspection**:
  - Reads `world/playerdata/<UUID>.dat` via `NbtIo.readCompressed`.
  - Loads inventory tags into a virtual container.
  - Upon menu closure, modifications are written back to the `.dat` file atomically (`.tmp` swap).
- **Curios Compatibility**:
  - Checked via reflection/service loader (`ModList.get().isLoaded("curios")`). If present, accessory slots are appended to the inspection view.

### 3.4 Protection & Chunk Quarantine (`protection/`)

- **Ban-Item**:
  - Intercepts `PlayerInteractEvent.RightClickItem` (`NO_USE`).
  - Intercepts `PlayerInteractEvent.RightClickBlock` and `BlockEvent.EntityPlaceEvent` (`NO_PLACE`).
  - Intercepts `EntityItemPickupEvent` and inventory ticks (`TOTAL`).
- **Chunk Quarantine**:
  - Wraps risky block entity ticks or handles unhandled tick exceptions.
  - Corrupted entities or block entities that would cause server crash are stripped, logged to `instaff/quarantine.log` with exact world XYZ coordinates, and cleanly removed.

## 4. Invariants and Golden Rules

1. **Server Thread Stability**: No exception from any module is allowed to bubble up and crash the server.
2. **Monotonic Timings**: Never use `System.currentTimeMillis()` for logic; always use `Util.getMillis()`.
3. **Atomic File Writes**: Any disk write must write to a temporary file (`.tmp`) first and atomically replace the destination file using `Files.move(..., StandardCopyOption.REPLACE_EXISTING)`.
4. **Complete Internationalization**: Every message rendered to staff or players must use `LocalizationHelper` and be defined in both `en_us.json` and `pt_br.json`.
5. **No Vanilla Client Incompatibility**: Unless using the optional client integrity feature, all other features must be 100% server-side and fully compatible with vanilla clients.
